# 仓库、记录与迁移

GitHub 版本库只管理源码、说明文档、测试及虚构 Excel 样例。`.gitignore` 排除了本机聊天、任务、微信授权、运行日志、实际成果、二维码和依赖。推送本身不会删除这些本机文件；GitHub 也不是它们的备份。

## 需要保留的状态

- `data/pilot.sqlite3`：聊天、待办、流程、确认与消息去重记录。备份时使用 SQLite 的一致性备份，或者先停止任务服务再备份；不要只在数据库写入时复制一个主文件并忽略其日志。
- `outputs/`：实际生成的成果、验收文件与输入快照。只迁移数据库而缺少这些文件，历史成果验证可能失败。
- 实际项目资料及 `projects/excel-demo/模拟收件箱/`：按是否需要保留迁移。
- 当前 Windows 用户目录下 `.openclaw-zhishi-pilot/`：微信凭据、绑定和桥接密钥。该目录位于仓库外，不应提交到 GitHub。换机器建议重新扫码，不保证凭据直接复制后可继续使用。

同机同用户更换项目目录通常可沿用授权，但需更新微信配置内的本地插件路径。历史任务计划可能含绝对输入路径及版本摘要，不能简单全局替换而跳过校验；建议先完成进行中的流程，再迁移，并单独检查待处理任务。

## 新电脑部署

1. 克隆源码，准备兼容的 Python 环境。当前在 Windows、Python 3.14 验证，Python 服务只用标准库。
2. 单独准备项目所需的 Node、OpenClaw、官方微信插件及隔离配置。原机运行时在项目 `.runtime/`，未提交版本库。
3. 准备 Excel 执行库。当前依赖 Codex 附带的 `@oai/artifact-tool`，`workflows/node_modules` 是目录联接；GitHub 不包含该联接或运行库。通过 `EXCEL_WORKER_NODE` 配置兼容 Node，另行配置模块解析。尚未封装为独立安装程序或跨平台部署镜像。
4. 如需保留历史，恢复一致性数据库备份、成果和项目资料，检查路径及未完成流程；不需要历史时由程序新建本地数据库。
5. 停止旧电脑的任务服务和微信网关，再在新电脑完成微信扫码与绑定，避免两台机器同时处理同一任务或会话。
6. 保持原型的本机监听范围，启动服务并验证微信收发、文件处理和 ABC 流程，之后再启用正式定时工作。运行期间保持电脑开机联网、不休眠。

已有源码推送不会替代上述状态备份。不要使用清理未跟踪文件的命令删除运行目录；这些数据被 Git 忽略，但仍由本机服务使用。

当前默认不调用模型。以后启用模型时，应在目标机器重新配置服务端环境变量，密钥不写进仓库。
