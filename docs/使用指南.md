# 知事使用指南

知事是一款**以微信为交互入口的企业级主动式智能体**。它按照任务安排，主动联系负责人和执行人员，跟进回复，调用已配置的技能，核对成果并汇报结果。

员工通过微信接收和处理任务；管理员通过桌面工作台配置人员、安排工作、查看进度和处理异常。

本指南对应当前桌面工作台。实际可用的协作流程取决于已部署的运行环境、任务模板和技能配置。

## 一、首次使用

### 1. 启动知事

在包含 `app.py` 的项目目录中打开终端，运行：

```powershell
python app.py
```

然后在浏览器打开：

```text
http://127.0.0.1:8765/
```

页面显示“服务已连接”，表示工作台可以访问知事服务。模型接口和微信连接需要分别检查。

定时派发和后台处理期间，电脑需要保持开机、联网，知事服务需要持续运行。

### 2. 了解工作台

| 页面 | 用途 |
|---|---|
| 工作台 | 查看任务概况、任务动态和最近任务 |
| 任务清单 | 创建安排、查看进度、处理异常和下载成果 |
| 对话助理 | 查看任务通知与人员回复，处理普通待办或本地模拟对话 |
| 账户管理 | 添加员工、连接微信、编辑资料及停用连接 |
| 设置 | 配置 AI 协作接口和普通待办理解方式 |

## 二、添加员工并连接微信

进入 **账户管理**：

1. 点击“添加员工”，填写姓名、微信备注和工作备注。
2. 保存后，点击这位员工的“连接微信”。
3. 由员工本人使用微信扫码，并在手机上确认授权。
4. 按页面提示完成连接，检查是否在线。
5. 正式派单前，核对微信实际收发情况。

姓名和微信备注用于识别员工，实际消息收发以扫码授权的连接为准。

已有连接可能由负责人和员工1共用。为任务选择人员时，应核对实际接收账号，避免将多个角色误认为多个独立微信。

### 停用、删除和恢复

- **停用连接**：停止后续微信收发，保留授权资料；不会自动取消业务任务。
- **删除员工**：员工移出正常列表，对应连接停用，任务记录和授权资料保留。
- **恢复员工**：在“已删除”筛选中恢复资料，再重新扫码连接微信。

已经提交到微信的消息不能通过这些操作撤回。

## 三、配置 AI 协作接口

需要通过模型理解负责人和员工回复时，进入 **设置 → AI 协作接口**：

1. 填写服务商提供的接口地址、模型 ID 和 API Key。
2. 点击“保存并应用”。
3. 点击“测试连接”。
4. 根据测试结果检查配置。

连接测试只发送测试请求，不启动业务任务，也不联系员工。测试通过表示本次接口调用符合要求，不代表完整协作流程已经验证。

已有密钥不会回显。保持密钥输入框为空并保存，会沿用同一接口地址下的已有密钥；更换接口地址时，需要重新填写。

“日常待办理解”与“AI 协作接口”分别配置。普通待办可使用规则模式，无需先配置模型。

## 四、创建任务

在工作台或任务清单中点击 **新建任务**，根据工作内容选择类型。

| 任务类型 | 适用情况 | 完成方式 |
|---|---|---|
| 普通待办提醒 | 提醒本人处理一件事 | 标记完成、取消或延期 |
| 自定义员工任务 | 向一名或多名员工派发工作并跟进 | 所有执行员工完成后结束 |
| 已有协作模板 | 按已配置流程分工、执行技能和核对成果 | 达到该模板的完成条件 |

### 1. 普通待办提醒

选择“普通待办提醒”，填写内容和未来的提醒时间，提交即可。

也可以在 **对话助理 → 日常待办助理** 中输入：

```text
30 分钟后提醒我回复客户
我的待办
```

修改待办时，可使用任务按钮，或按实际编号回复：

```text
完成 1
取消 1
10 分钟后提醒 1
```

延期会调整下一次提醒时间，保留原截止时间。

### 2. 自定义员工任务

1. 选择“自定义员工任务”。
2. 填写任务内容。
3. 选择安排时间，时间按北京时间处理。
4. 勾选一名或多名执行员工。
5. 提交后，到安排时间由知事主动派发。

员工收到微信通知后，按通知中的实际任务编号回复：

```text
任务编号 收到
任务编号 完成
```

不要直接发送上面的占位文字，应复制通知中的完整编号。

“收到”表示接单，“完成”表示该员工完成工作。多人任务需全部执行员工完成后才结束。管理员也可在详情中“代记已接单”或“代记已完成”，记录会注明代记。

自定义员工任务用于派单和跟进，不会仅凭任务文字自动生成新的业务技能或验收流程。

### 3. 已有协作模板

选择已有模板，分别指定负责人、员工1和员工2，填写安排时间后提交。

任务到时启动，后续按照模板推进。以商品核查流程为例：

1. 知事联系负责人，确认是否开始。
2. 向员工1派发准备任务。
3. 员工1准备文件，知事检查输入。
4. 员工1核对输入摘要。
5. 知事交接给员工2，执行已配置的比对技能。
6. 员工2核对成果。
7. 最终校验通过后，知事向负责人汇报。

员工按当前通知回复，例如“开始吧”“导好了”“核对过了”。在成果核对阶段，“收到”只表示收到消息，不等于验收通过。

同时有多件工作等待回复时，按知事给出的选项选择对应任务。以最新通知和实际阶段为准。

## 五、查看进度和成果

进入 **任务清单**，可按状态、编号、名称及创建日期筛选任务。

打开任务详情，可查看：

- 当前阶段和待处理事项；
- 各员工的接单、完成情况；
- 通知与回复记录；
- 受阻原因及可用处理按钮；
- 已生成的成果和下载入口。

点击“查看任务对话”或“对话记录”，可查看对应工作的通知与回复。

绑定微信的流程需要由对应人员从绑定微信回复；网页不会代替员工确认。本地模拟流程则按页面提示操作。

## 六、更正任务文件

商品核查或发票任务需要替换文件时：

1. 打开任务详情。
2. 点击“上传文件更正任务”。
3. 选择需要替换的位置。
4. 上传文件并填写更正说明。
5. 保存后，按新通知重新核对。

单个文件最大 **20 MB**。输入文件和发票导出文件使用 `.xlsx`；商品核查结果使用 UTF-8 编码的 `.csv`，并需通过原有校验。

更正会使相关旧确认失效。员工应以新版本通知及附件为准，不要继续确认旧版文件。“文件更正记录”中可查看此前上传的版本。

## 七、看懂通知状态

| 状态 | 含义与处理 |
|---|---|
| 等待发送 | 通知已排队，等待后台处理 |
| 正在提交 | 正在调用消息通道，等待结果 |
| 已提交微信，送达未确认 | 通道已接受，仍需核对手机是否实际收到 |
| 本地模拟消息 | 消息仅显示在网页中 |
| 发送受阻 | 根据提示检查微信连接、文件或配置 |
| 发送结果未知 | 先核对手机和任务记录，避免重复发送 |

“已提交微信”不等于员工已读，也不等于工作完成。

## 八、常见问题

| 问题 | 处理方法 |
|---|---|
| 页面打不开 | 检查服务是否运行，确认访问地址和端口 |
| 员工没有收到派单 | 查看任务通知状态，再检查账户管理中的微信连接 |
| 派发受阻 | 处理详情中的错误后，使用可用的“重试派发”或“重试派单”按钮 |
| AI 回复处理失败 | 在设置中测试接口；修复后，按详情提示重试失败回复 |
| 提示任务阶段已变化 | 刷新任务，查看最新通知，再进行操作 |
| 文件已准备，但任务没有结束 | 继续完成输入检查、人员核对及最终校验等后续步骤 |
| 没有可用模板 | 由管理员准备本地项目说明、任务配置、输入文件及对应技能 |

## 九、从 GitHub 源码部署时

GitHub 当前版本包含源码、示例配置和说明文档，不包含本机的数据、聊天、任务记录、授权、密钥、运行依赖和证据包。

获取源码后，还需按所用功能准备：

- Python 3.11 或更新版本；
- 微信接入所需的 Node、OpenClaw 和插件环境；
- 自己的模型服务配置；
- 文件处理所需的运行库；
- 业务模板、输入文件和数据库环境。

复制源码不会恢复原电脑上的记录和微信授权。

当前桌面工作台使用本机管理模式；多人后端需要另行初始化和部署。在账户管理中添加微信连接，不等于创建多人后端登录账号。

## 十、保留数据与记录

日常使用中，应分别保管：

- `data/`：任务、聊天、配置及部分授权状态；
- `outputs/`：成果文件和相关输入快照；
- 本地项目配置与业务输入文件；
- 独立保存的微信授权资料；
- 数据库备份和证据包。

不要只备份源码。数据库写入期间，应使用项目提供的一致性备份工具；迁移到其他电脑时，还需核对成果文件、配置、运行依赖和微信连接。
