# 两段式任务验证操作

本次使用固定示例文件，由本人依次扮演 A、B。无需配置模型 API，执行内容均为已登记的固定技能。可选择本地网页验收，或把两段通知和材料发送到本人绑定微信；不向其他联系人分发。

## 微信模式：A、B 均为本人

1. 在已绑定的 ClawBot 微信会话中发送“开始微信两段式验证”，或在网页点击“开始微信模拟”。已有未完成的同通道任务时不会重复启动。
2. 收到“角色 A｜第一段待验收”：附整合 Excel、预览图和异常清单。核对后复制消息里的完整口令，例如 `确认第一段 PAIR-20261101-ABC123 V1`。
3. 后台保存 A 的确认并自动交给 B。收到“角色 B｜第二段待验收”：附 A 的交接 Excel、B 的部门汇总 CSV，并在文字中列出两个部门的金额。
4. 核对后回复通知中的完整“确认第二段 … V1”口令，流程结束，并向同一个微信提交完成回执。

两个角色都固定到发起时的本人绑定账号和会话。角色、阶段与版本在每条验收通知中明确标出。绑定发生变化时阻止旧材料发送；通知超时或重启前发送中断时，记录未知结果，不自动重复发送。接口成功只表示已提交通道，手机收到和已读仍需实际核对。

本地网页模式不会发送这些通知；切换通道前需完成当前未结束的实验。旧的本地记录不会因启用微信功能而自动补发。

## 页面操作

打开 <http://127.0.0.1:8765/two-stage>，侧栏入口为“协作验证”。

1. 如果还没有执行记录，点击“开始两段式验证”。第一段读取现有两份示例 Excel，执行统一字段、去重和异常隔离。
2. 查看第一段的工作簿、预览和异常清单。预期输入 8 行，保留 6 行，去重 1 行，隔离 1 行，合计 5,000.75。此时 B 显示等待，尚未执行。
3. 点击“以模拟 A 身份确认第一段”。确认记录与 A→B 交接事件一起保存，B 无需再次手动启动。
4. 等待第二段显示部门汇总。B 实际读取 A 已确认的 XLSX，按部门计算，不直接复用第一段的合计作为汇总结果；独立计算后再核对总数。
5. 核对销售一部 3 行、1,850.75；销售二部 3 行、3,150.00；总计 6 行、5,000.75。可下载部门汇总与交接单，查看来源版本和文件摘要。
6. 点击“以模拟 B 身份确认第二段”，页面显示“两段式验证完成”。之后可点击开始发起新一轮。

如果材料变化导致校验失败，页面会阻止交接或确认，并显示原因。修复输入后重新发起一轮验证。

## 对话操作

也可使用工作台聊天框操作。当前已绑定的微信会话可以输入同样口令；本地模式材料在网页检查，微信模式会主动发送两段验收材料。任务编号以页面或微信实际显示为准。

```text
开始两段式验证
开始微信两段式验证
两段式进度
确认第一段 PAIR-20261101-ABC123 V1
确认第二段 PAIR-20261101-ABC123 V1
```

每次确认必须包含完整任务号和版本。重复确认不会重复生成交接事件或再次执行第二段。

如果微信发出确认后没有回应，先查看工作台的微信状态及两段式进度。接收网关离线时，后台会尝试使用已保存授权恢复，不会主动重新申请二维码。不要连续重复发起新任务，也不要在网页替代确认来掩盖通道故障。

微信通知通过正在运行的网关 RPC 发送；请勿在同一授权目录中另开独立的 `message send` 运行时，以免争用状态所有权并中断接收。接口返回成功只代表通道提交，手机可见情况仍需人工核对。

## 实际验证范围

- 第一段完成但尚未确认时，第二段不会执行。
- 第一段确认后，交接入队，第二段自动执行。
- 交接绑定 A 的成果版本与文件摘要；文件变化会阻止后续处理。
- 两段分别验收，A 的确认不等于 B 的最终确认。
- 重启后保留待确认状态和待处理交接；被中断的本地衍生文件处理可重新执行。
- 这是单进程本机实验，不能据此声称支持生产环境多进程调度或外部副作用的恰好一次执行。

当前没有真实员工登录、权限隔离或大模型自主规划。页面中的角色只用于验证顺序，不能作为真实身份依据。后续接入两名真实员工与模型 API 时，要单独验证身份、资料权限和模型执行质量。

## 自动自检

```powershell
python scripts/verify_two_stage.py
```

该自检实际运行两段技能，使用独立临时数据库，并自动模拟 A、B 确认。不会修改工作台中的人工确认记录，也不调用消息发送通道。自检材料保存在独立任务号目录，结果另存“自动自检结果.json”。

2026-11-01：真实技能自检已通过，部门汇总为 1,850.75 和 3,150.00。另在隔离数据库的测试网页中点击验证了开始、等待 A、确认 A、自动执行 B、确认 B 的完整流程。人工演示实例单独停留在第一段等待确认，等用户亲自操作。
