## 运行

需要 Python 3.11 或更新版本；本次在 Windows / Python 3.14.4 验证。待办服务仅用 Python 标准库；新增 Excel 执行器使用本机 Codex 自带 Node 与 `@oai/artifact-tool`，并通过 `workflows/node_modules` 目录联接使用。

```powershell
Set-Location -LiteralPath 'D:\desktop\项目工程\wechat-assistant-v01'
python app.py
```

浏览器打开 <http://127.0.0.1:8765>。服务已在运行时直接打开即可。停止用 Ctrl+C。也可运行同目录 `start.ps1`。

换端口：`python app.py --port 8766`。

程序只监听本机地址，固定绑定 `pilot-owner`，没有企业登录系统。请保持这一访问范围。扩大到员工时需要按《方案与接入.md》增加受控入口和账号授权。

## 两分钟体验

1. 点击“体验 10 秒提醒”。
2. 等待约 10 秒，右侧出现主动提醒，提醒记录增加一条。
3. 回复“10 分钟后提醒 1”（编号以实际事项为准），观察下次提醒更新，原截止时间保留。
4. 回复“完成 1”，事项完成，取消后续提醒。
5. 重启程序，待办、聊天和发送记录保留在 `data/pilot.sqlite3`。

也支持：

```text
30 分钟后提醒我回复客户
提醒我 2026-11-03 09:00 提交方案
我的待办
完成 1
取消 1
10 分钟后提醒 1
```

规则模式只支持上述明确表达。输入含糊时会请你补充，不会自动猜测时间。完成和取消要带事项编号。

每条计划到点提醒一次，之后等待用户完成或重新设置“稍后提醒”。**尚未实现**日简报、周期任务、安静时段、每日提醒上限或自动升级催办，不能把这些下一阶段能力作为已交付功能验收。

## 模型可以替换

默认规则模式，无模型调用。设置环境变量后重启服务，再在“模型与接入”选择模型模式。`.env.example` 是参考，本程序不会自动读取 `.env`。

```powershell
$env:MODEL_BASE_URL = 'http://127.0.0.1:4000/v1'
$env:MODEL_ALIASES = 'reminder-fast,planner-strong'
# MODEL_API_KEY 在本机设置，不要填进聊天或提交到版本库。
python app.py
```

`MODEL_BASE_URL` 指向你信任的 LiteLLM 或兼容 Chat Completions 的接口。密钥仅从服务端环境读取，不出现在浏览器配置返回值中。自托管服务调用外部模型时，输入仍会发送到所选模型供应商。

`litellm.config.example.yaml` 给出两个模型别名的配置模板，需要替换供应商端点和模型名。当前页面可选择一个意图理解模型，自动按任务分配模型、故障备用和企业预算应在部署网关时设置，不由本原型模拟冒充。

明确指令仍优先由规则处理。仅未匹配规则的文本发给模型；模型只返回结构化操作，所有写入由业务服务校验。不会让模型运行终端、访问员工其他文件或任意选择事项归属。

模型接口已用替身响应验证请求与解析，**没有使用真实密钥进行模型联调**。

## 验证

```powershell
python -m unittest discover -s tests -v
```

检查了重启后提醒恢复、同一版本只提醒一次、完成停止提醒、延期保留截止时间、重复请求不重复建任务、归属隔离、过去时间拒绝、含糊指令澄清、模型编号不能凭空操作、模型别名传递及密钥不返回前端。

这里的归属检查只是业务代码中的基础验证，**不代表已经实现多用户身份认证或企业级安全隔离**。SQLite 和本地线程是试点实现；扩大服务前需要持久队列、认证、并发与故障演练。
